# POEM 2.11 — Full offline field reliability

Baseline: 2.10.0. One forward migration, the existing encrypted IndexedDB upgraded in place from version 1 to 2, no dependency updates, no database reset. Existing drafts, queued request IDs, device encryption key, template versions, NGO isolation, canonical records and volunteer self-publication are preserved.

## Delivered workflow

1. Open **Offline field** while online, find assigned projects and download the projects needed for fieldwork. Each download is authorized and audited on the server. The encrypted bundle includes the pinned template, project/policy/consent, geography and up to 200 collector-owned reference people, households and editable responses. Assignment discovery is capped at 200. It is not a full NGO directory export; use online search for additional references.
2. A production service worker caches only the built application files. After installation and an online sign-in, reopening the root app URL offline can enter the downloaded field workspace using the retained local owner marker. An offline reopen does not wait for a network token refresh. This is local cache access, not an assertion of current server permission.
3. Collect JSON answers and JPG/PNG/PDF files offline. Attachment metadata and bytes are encrypted and committed in one IndexedDB transaction before returning the local reference to the form. The existing 5 MiB/file limit remains, with a 50 MiB per-account device attachment limit and estimated free-space checks. A retained-file picker recovers files saved before a form interruption.
4. Saving or submitting creates a durable request. Attachment bytes are uploaded before the survey RPC. Stable client attachment UUIDs make reservation retries idempotent. The upload URL is encrypted on the device; HEAD recovers server offset, expired upload URLs are replaced, and an already committed object is checked before another upload. A quota failure persisting the upload URL stops before sending bytes. No upsert is used.
5. Resolved server attachment IDs are persisted to the original queue entry before the first survey RPC. Its request UUID remains unchanged. Lost survey acknowledgements replay the existing server receipt. Acknowledged response IDs are atomically recorded on-device while removing the queue entry.
6. The workspace shows saved-local drafts, queued/syncing requests, failed copies and synchronized receipt history, plus attachment transfer states and server-confirmed progress. Sync runs in the foreground on reconnection, every 30 seconds while open and from **Sync now**. Manual sync bypasses the automatic retry delay. Web Locks serialize queue sync across tabs where supported; stable server IDs and receipt semantics remain the correctness guards where Web Locks are unavailable.
7. Downloaded collection access expires at the earlier of seven days or project end. Reconnect to refresh expired/denied bundles. Server policy, assignment and identity-verification gates always apply at synchronization. Optional template tokens explicitly reject stale downloaded templates without breaking older payloads. Published template versions remain immutable.
8. Confirmed server rejections can be recovered for editing; uncertain saves must retry their original request. Refresh the project first, reopen the recovery draft, review current consent and correct the answers. **Renew device attachment consent after policy correction** creates new references from retained bytes when renewed evidence consent is needed. It never rewrites the original queued request or reservation.
9. Active draft writes are awaited before main-workspace navigation, switching into the field workspace and signing out. Explicit form close saves the latest draft. A browser-close warning covers an active edited form. Abrupt OS/browser termination can still interrupt an in-flight write; rely on the displayed saved time and reopen/review after an interruption.
10. Sign-out locks device access while retaining unsynchronized copies. A successful online sign-in is required to unlock retained data. Another account cannot read those copies through the app. **Clean acknowledged copies** retains all attachments if any local draft/queued request still exists, then removes uploaded local bytes and receipt history when safe to do so. **Erase my device data** is a separate explicit destructive confirmation for all this account's local copies; server records and other accounts' copies remain.

## Operational boundaries

This is an implemented offline release awaiting real browser/mobile and Supabase Storage acceptance. The build environment has no Docker daemon or installed browser binary. Protocol tests use mock HTTP, storage tests use real WebCrypto with a serialized IndexedDB model, and SQL tests use PGlite. Do not describe these as actual airplane-mode, HTTP Storage, camera or mobile acceptance.

Service-worker offline reopening applies to the root URL of the production build on the same origin. Development Vite mode does not install the worker. Auth/reset endpoints and backend/file responses are never cached. New worker versions wait until old tabs close; they do not force-reload a field session. Reopening an auth callback URL offline is not supported; open the root app URL.

Uploads pause when the page closes and resume after reopening and synchronizing. There is no service-worker Background Sync handler or promise that a closed mobile browser will upload. TUS chunk size is 6 MiB; because the current file cap is 5 MiB, many files complete in one final chunk. Interrupted uncommitted bytes can need retransmission; acknowledged bytes are recovered using server offset or the committed-object check.

The nonextractable AES key lives in the same browser origin as the ciphertext, as in prior releases. Encryption and owner checks do not provide isolation from a compromised browser/origin or a person controlling its developer tools. On a shared device, close other POEM tabs, resolve outstanding work, explicitly erase the account's device copies if needed, then lock/sign out. Do not clear browser storage or change origin until pending work is synchronized. Remote revocation cannot erase already downloaded information while a device is disconnected.

Reference downloads are deliberately bounded; users should not infer that absence in the offline list means a beneficiary does not exist. Corrupted/unreadable copies are retained rather than automatically deleted; recovery may require the original evidence file. Detached, failed or unused device files are retained unless the owner explicitly erases them. No automatic server evidence purge, malware scanner, retention deletion, payment or scoring functionality is added.

## Implementation references

The transport follows [Supabase resumable upload guidance](https://supabase.com/docs/guides/storage/uploads/resumable-uploads) and the [TUS 1.0 protocol](https://tus.io/protocols/resumable-upload). Real local/cloud endpoint compatibility is an acceptance gate, including Location origin, HEAD/PATCH support and Storage metadata.
